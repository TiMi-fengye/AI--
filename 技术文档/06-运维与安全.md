# 06 运维与安全

> 当前账号与权限以[07](07-手机号账号与数据权限.md)为准；网站源码修改授权、只读代码与仓库保护以[10](10-源码保护与变更管理.md)为准。以下保留部分历史运维记录，旧第三方登录流程已停止。

## 1. 日常健康检查

```bash
sudo systemctl is-active hr-system.service
sudo systemctl is-active nginx.service
curl -fsS http://127.0.0.1:8080/ > /dev/null
curl -fsS http://127.0.0.1:8080/api/auth/status
df -h
free -h
```

公网检查：

```bash
curl -I http://YOUR_ECS_IP/
```

## 2. 日志

systemd 日志：

```bash
sudo journalctl -u hr-system.service -n 100 --no-pager
sudo journalctl -u hr-system.service -f
sudo journalctl -u nginx.service -n 100 --no-pager
```

Nginx 默认日志：

```bash
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

不要把 `server/config.json`、请求体、用户快照或飞书 Token 写入日志。

## 3. 数据备份

每日备份工具已开发，生产安装与定时启用仍待服务器 `DAILY_BACKUP_READY` 成功回执。完整机制、安装方式和状态以 [11-每日备份与恢复](11-每日备份与恢复.md) 为准。

安装成功后，`hr-system-backup.timer` 每天北京时间（`Asia/Shanghai`）02:00 执行，停机错过时恢复后补跑。服务器私有地址为 `123.56.175.4:/var/backups/hr-system/daily/`，仅 root 可访问；每份使用实际完成时间命名为 `YYYY-MM-DD_HH-MM-SS+0800-随机后缀`，同日手动重跑不会覆盖旧备份。保留全部成功备份，不自动删除，需定期检查空间。

在服务器 root 终端检查和操作：

```bash
hr-system-backup --list
systemctl list-timers hr-system-backup.timer --all
systemctl status hr-system-backup.timer --no-pager
journalctl -u hr-system-backup.service -n 20 --no-pager
hr-system-backup --run
# 将下面目录替换为 --list 中选定的真实时间戳目录
hr-system-backup --verify /var/backups/hr-system/daily/所选时间戳目录
```

备份包括程序和配置、实际数据目录、服务配置、运行环境，以及启用 MySQL 时的 SQL。工具检查文件及数据库稳定窗口，完整校验后才发布成功目录；备份不会停止或重启业务服务，也不修改现有源码保护。备份可能包含凭据和人员资料，不得提交 GitHub 或通过网站公开下载。当前仅提供本机备份，独立存储或阿里云 OSS 副本尚未配置。

## 4. 数据恢复

恢复统一按 [11-每日备份与恢复的“按时间戳恢复”](11-每日备份与恢复.md#按时间戳恢复) 执行。先选择并校验完整时间戳目录、保全当前状态，再在维护窗口恢复同一份备份中的数据库、账号/组织文件、程序及相关配置；不能混用不同日期的材料，也不能将恢复文件快照当作 MySQL 主数据已恢复。保留源码由 root 管理、应用数据按需可写的权限分离。

`hr-system-backup --verify` 只校验，不会覆盖生产。本次交付不执行实际恢复；具体恢复命令须根据选定备份和当前故障状态制定。

不要在未备份的情况下使用 `/api/data/*.json` 的 DELETE 接口，也不要在系统管理中点击“重置数据”后再尝试恢复浏览器缓存。

## 5. 安全基线

- SSH 使用密钥登录，关闭密码登录；如果暂时使用密码，完成部署后立即更换临时密码。
- 安全组只开放 22、80；配置 HTTPS 后再开放 443，保持 8080 关闭公网访问。
- 将 SSH 22 来源限制为管理员固定公网 IP。
- `server/config.json` 保留应用账户所需的原位写入权限和 `600` 模式，数据目录保持应用账户可写；源码保护启用后代码文件与代码目录由root管理，不能对整个应用目录递归chown给运行账户。
- App Secret 不写入 HTML、JS、README、截图和工单。
- 飞书应用使用最小权限和明确的可用范围，发布版本前核对机器人可见范围。
- 公开站点建议使用域名、HTTPS、有效证书和定期证书续期。
- MySQL 只监听 `127.0.0.1`，数据库密码保存在 `/etc/hr-system/mysql.env`，权限保持 `600`。
- 当前API已使用服务端HttpOnly会话与角色/楼栋范围校验；业务管理员权限不授予代码编辑、GitHub或SSH权限。敏感API保持no-store。源码负责人文件及SHA256记录不能代替仓库保护和服务器权限。

## 6. 常见故障排查

### 页面打不开

1. 检查阿里云安全组 TCP 80 是否放行。
2. 检查 `systemctl is-active hr-system.service`。
3. 检查 `ss -ltnp` 是否监听 80 和 8080。
4. 查看 Nginx 错误日志和 systemd 日志。

### 502 Bad Gateway

通常是 Node 服务停止或 8080 监听地址错误：

```bash
sudo systemctl restart hr-system.service
curl -I http://127.0.0.1:8080/
sudo nginx -t
```

### 微信登录失败

- 检查微信开放平台授权回调域名是否为当前公网域名，完整回调地址是否为 `http://YOUR_ECS_IP/api/wechat/callback`。
- 检查 AppID、AppSecret、服务端时间和 `api/wechat/login-config`。
- 未配置凭据或登录开关关闭时，登录页不会显示微信按钮；这是预期行为。

### 飞书消息发送失败

- 检查机器人能力是否开启。
- 检查 `im:message` 或后台对应的“获取与发送单聊、群组消息”权限。
- 群聊接收对象必须是 `chat_id`，且机器人已加入群聊。
- 用户接收对象必须使用正确的 `open_id`、`user_id` 或 `union_id` 类型。

### 更新后仍显示旧页面

- 检查 `index.html`、`login.html` 的资源版本参数。
- 执行 `systemctl reload nginx`。
- 使用 Ctrl+F5，检查浏览器 Network 是否命中最新 JS/CSS。
- 确认服务端没有残留旧工作目录或旧 systemd `ExecStart`。

## 7. 变更记录建议

每次上线记录日期、版本标识、修改文件、数据备份位置、执行人、验证结果和回滚包位置。飞书 App ID 可以记录，App Secret 和 Token 不记录。
