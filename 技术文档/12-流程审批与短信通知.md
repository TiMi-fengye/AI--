# 流程审批与短信通知

2026-11-23 更新。此版本处于开发和发布验证阶段，生产生效以固定版本发布成功回执为准。

| 申请 | 审批和通知 |
| --- | --- |
| 费用加班、调休加班 | 楼长审批通过 → 区域经理审批通过 → 最终批准 |
| 调休请假、替班请假 | 楼长审批通过即批准，并生成向同区域经理发送短信的通知任务 |
| 法定年假、福利年假、带薪病假 | 楼长审批通过 → 区域经理审批通过 → 最终批准 |
| 其他原有请假类型 | 继续沿用楼长单级审批 |

任一级拒绝即结束申请。两级审批的一审通过仍是待审批，不计入已批准加班、可用调休或最终请假统计；终审通过后再按原有业务规则计算。管理员可按当前阶段代审，仍需分别完成两个阶段。删除继续仅管理员可操作，不提供通过删除重建或快照导入伪造审批结果的入口。

管理员在账号权限管理中选择“区域经理”，分配负责区域，并核对经理账号绑定手机号；在人员档案中正确填写区域和楼栋。区域经理按人员档案的区域获得审批范围，楼长仍按授权楼栋处理一审。区域经理仅开放申请审批及本人的资料、申请和小时数，不授予区域人员编辑、导出、删除或系统设置权限。角色不会根据岗位名称、注册表单或浏览器提交参数自动授予。

申请状态继续使用 pending、approved、rejected，另用 approvalStage 区分 leader、regional、complete；服务端记录审批历史。旧的已批准、已拒绝记录不重新审批、不补造历史，旧待审批记录按楼长阶段处理。进入区域经理审批或结束的记录不能修改申请业务内容，避免审后变更加班时长、假期类型和日期。普通快照保存不能伪造审批状态、阶段和历史。

审批使用独立接口 `POST /api/approvals/{overtime|leaveRequests}/{id}`，提交 decision 及 expectedRevision。服务端重新核对登录身份、阶段、负责范围及版本；页面等待服务器保存并重新加载权威数据后展示结果。重复审批、旧版本或越权操作被拒绝。

短信通知任务与调休/替班请假的批准记录一起持久保存，任务内容不下发到业务快照。短信未配置、无对应经理或缺少有效手机号时保留 blocked 状态；pending 表示待处理；sent 只表示短信平台受理，不表示运营商已送达。超时或无法确认发送结果使用 uncertain，管理员核实后再决定是否承担重复发送风险重试。短信失败不撤销已经保存的批准结果。

短信使用独立的 `approvalSms` 配置或 `HR_APPROVAL_SMS_*` 环境变量，见 [审批短信环境示例](../deploy/approval-sms.env.example) 与 [公开配置示例](../server/config.example.json)。默认关闭，不改变登录验证码开关。需要阿里云审核通过的短信签名和通知模板，模板参数为 employee、type、start、end、hours；真实凭据只填入服务器私有配置，不能提交 GitHub 或写入架构 HTML。当前尚未配置真实短信服务，不能宣称已经发送或送达。

通知状态通过有权限的管理者读取，返回状态而不返回收件手机号；仅管理员可重试。超时及重复请求测试使用注入的模拟发送器，不发送真实短信。恢复操作仍遵循 [每日备份与恢复](11-每日备份与恢复.md)，发布保留源码保护和每日备份。

短信平台受理和送达不同，超时需核对后再重试；接口参数及审核要求以[阿里云 SendSms 官方文档](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)为依据（2026-11-23核对）。
