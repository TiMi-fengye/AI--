# 02 前端技术说明

## 1. 页面入口和加载顺序

`login.html` 负责登录。用户名密码登录成功后跳转到 `index.html`。如果用户直接访问 `index.html` 且没有有效登录状态，`app.js` 会跳转回登录页。账号和会话目前保存在当前浏览器的 `localStorage`/`sessionStorage`，不同设备不会自动共享账号，也未实现跨设备统一登录。

`index.html` 按以下顺序加载脚本：

1. `store.js`：建立 Store 数据层。
2. `auth.js`：建立 Auth 登录和账号管理。
3. `app.js`：建立 App 路由、导航和弹窗。
4. `dashboard.js`、`employees.js`、`attendance.js` 等业务模块。
5. `App.init()`：初始化 Store、Auth、导航和当前页面。

脚本和 CSS 使用版本查询参数，例如 `?v=20261030feishuclient`。发布前修改版本号可以避免浏览器缓存旧文件；服务端同时对 HTML、CSS、JS 和 JSON 设置了不缓存响应头。

## 2. 模块职责

| 模块 | 主要职责 |
|---|---|
| `app.js` | 页面路由、侧边栏、页面标题、Modal、Toast、全局权限入口 |
| `auth.js` | 本地账号登录、Session、修改密码、用户管理、微信身份映射 |
| `store.js` | 所有业务数据的读写、服务器快照同步、结算和统计缓存 |
| `dashboard.js` | 人数、费用、楼栋、人员变化和调休时长概览 |
| `employees.js` | 人员增删改、楼栋、人员属性、导入导出；飞书绑定字段已移除 |
| `attendance.js` | 签到签退、加班申请、请假申请、审批、调休余额 |
| `leave.js` / `overtime.js` | 独立的请假和加班页面入口及辅助操作 |
| `cost.js` | 月度费用、部门费用、楼栋费用和明细 |
| `org.js` | 部门和组织层级展示 |
| `permission.js` | 员工与系统账号绑定、管理员/普通用户角色 |
| `admin.js` | 部门、数据管理、微信 OAuth 和飞书 Webhook 配置 |
| `feishu.js` | 服务端飞书 API 调用和通知；飞书登录入口已停用 |
| `wechat.js` | 微信扫码 OAuth 授权弹窗和回调消息接收 |

## 3. 渲染和状态管理

系统没有引入 Vue、React 等前端框架。各模块通过 `container.innerHTML` 生成页面，使用事件属性或模块方法处理操作。`App.navigate(page)` 根据页面名称调用对应模块的 `render(container)`。

数据访问统一通过 `Store`：

```javascript
var employees = Store.getEmployees();
Store.addEmployee({ name: "示例人员", department: "交付运维部" });
Store.updateLeaveRequest(id, { status: "approved" });
```

开发新功能时不要直接散落地操作 `localStorage`。需要新增数据时，应在 `Store` 增加读取、写入、迁移和统计逻辑，再由页面调用。

## 4. 本地存储和服务器同步

浏览器本地键名前缀为 `personnel_management_`，主要业务键如下：

| 键 | 内容 |
|---|---|
| `employees` | 人员信息 |
| `attendance` | 考勤记录 |
| `leave_requests` | 请假申请 |
| `overtime` | 加班记录 |
| `settlements` | 月度结算 |
| `departments` | 部门 |
| `org_structure` | 组织结构 |
| `update_logs` | 人员信息变更记录 |
| `stats` | 统计缓存 |
| `personnel_performance` | 绩效记录 |

Store 启用服务器同步后，会将快照 POST 到 `/api/data/snapshot.json`。参考部署以 MySQL 保存共享快照，JSON 文件仅作初始化和灾备。首次打开空浏览器时可以从服务器恢复快照；如果浏览器已有人员数据，不会自动覆盖本地数据。

## 5. 业务规则实现位置

- 费用加班和调休加班：`store.js` 的 `overtimeType`。
- 调休请假、请假、替班请假：`leave_requests` 的 `type`。
- 调休总时长、已使用和剩余：`Store.getTimeBalance(employeeId)`。
- 费用结算过滤调休加班和替班/调休请假：`Store._calcSettlement()`。
- 楼栋调休时长看板：`Dashboard._buildingTimeBalanceCard()`。
- 外包人员替班请假校验：`Attendance.lvSaveApply()` 与 `Store._isOutsourced()`。

费用加班不会计入调休余额；调休加班不会进入工资结算；调休请假和替班请假不产生请假扣款。

## 6. 账号与移动端边界\n\n公开源码不提供固定默认密码。首次访问 `login.html` 时应在当前浏览器设置至少 12 位的管理员密码；账号及登录状态保存在该浏览器，清理站点数据或更换设备后需要重新设置。HTTP 地址只支持普通网页访问，Service Worker 和完整 PWA 桌面安装需要 HTTPS 安全上下文。\n\n## 7. 前端开发流程

1. 在 `js/` 或 `css/` 修改代码。
2. 运行 `node --check 文件名.js` 做语法检查。
3. 启动 `node server/server.js`，打开 `http://localhost:8080`。
4. 使用浏览器开发者工具检查 Console、Network 和 Local Storage。
5. 修改 `index.html` 中对应资源的 `?v=` 版本号。
6. 发布前执行数据备份和整包部署，不要用测试数据覆盖服务器快照。

## 8. 前端注意事项

- 内嵌 HTML 字符串中的用户输入要经过现有转义方法，避免 XSS。
- 新增字段时同时考虑旧快照迁移和空值默认值。
- 账号页面、人员页面和数据看板使用深色主题，内联浅色背景需要在 `theme.css` 增加可读性覆盖。
- 浏览器登录和微信扫码授权是两条入口；微信 AppSecret 不进入浏览器。
