# 08 架构 HTML 维护

固定交付文件为根目录 [人力资源管理系统开发架构.html](../人力资源管理系统开发架构.html)。双击可在浏览器离线查看；页面内嵌样式、图形、脚本和结构化内容，无需联网或安装前端依赖，支持角色切换、模块搜索及打印 / 保存 PDF。

## 每次更新

1. 修改代码后，核对 [系统开发架构.source.json](./系统开发架构.source.json) 中架构、权限、存储和部署事实，同步 `updatedAt`。
2. 在 `updates/YYYY-MM-DD.md` 记录当日变化。该目录的记录会自动收录到 HTML。
3. 在项目根目录执行：

   ```bash
   node scripts/generate-architecture.cjs
   node scripts/generate-architecture.cjs --check
   ```

4. 交付源码与重新生成的同一个 HTML。README、模块文件、依赖声明、更新日志、发布辅助脚本等都纳入源码指纹；生成器不扫描私密运行目录。

开发过程中可执行 `node scripts/generate-architecture.cjs --watch`。它定期检查公开源码的指纹，有变化时重新生成 HTML，Ctrl+C 退出。自动生成会更新文件清单、依赖和日志；技术含义发生变化时，维护人员仍需更新结构化事实，生成器不会推测代码的业务语义。

## 校验与 CI

`--check` 不修改文件。HTML 缺失或其内容与当前公开源码不一致时，返回非零退出码；未发生变化时重复生成不会改动 HTML。

`.github/workflows/architecture-docs.yml` 在推送和 Pull Request 时执行校验。该配置同步到 GitHub 后生效；合并保护是否将该检查设为必需项由仓库设置决定。CI 只校验文档，不部署、不访问生产，也不修改源码。

## 日期与版本

`updatedAt` 为维护日期，按北京时间填写；业务基线、部署环境参考日期与文档日期分别展示。页面源码指纹反映本地公开源码内容，不代表服务器当前状态。生产版本信息必须以实际部署记录为依据。

## 网页发布

当前服务端只允许已列出的业务 HTML。离线查看无需修改业务服务；若需要网页 URL，必须在 `server/auth-service.js` 静态白名单明确增加本 HTML，并验证鉴权与私密路径保护未受影响。

`deploy/aliyun-2026-11-11.sh` 固定旧提交和归档校验值，不能拿它部署新的文档或代码。新发布应固定新提交、重新校验归档并使用匹配的文件清单，包含本 HTML 及必要代码；不要仅向旧脚本的清单追加新文件。生产环境、真实人员资料和配置始终另行备份与保留。

## 数据边界

生成器只扫描代码、脱敏模板、测试与项目文档的显式白名单，不读取数据库、运行配置、账号文件、日志或环境变量。HTML 中不写真实服务器凭据或人员资料；源码指纹也不包含这些运行数据。
