## 2. 端口和访问路径

```text
客户端 -> TCP 80 -> Nginx -> 127.0.0.1:8080 -> Node.js
```

安全组建议：

| 端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | 管理员固定公网 IP | SSH 运维 |
| TCP 80 | `0.0.0.0/0` 或企业出口 IP | 网站访问 |
| TCP 443 | 配置 HTTPS 后开放 | HTTPS 访问 |
| TCP 8080 | 不开放公网 | Node 内部端口 |

示例入口使用 HTTP。公开部署应接入域名、申请证书并改成 HTTPS；飞书消息服务也应使用 HTTPS 域名。微信、飞书登录自 2026-11-11 版本起停用。

## 2.1 手机端访问与安装

手机直接打开 `http://YOUR_ECS_IP/login.html`，使用手机号注册、手机号加密码登录；管理员可使用管理账号登录。已有手机号人员档案需由管理员关联账号，注册不会自动认领。页面已采用响应式布局，侧边栏会切换为手机抽屉菜单。

完整 PWA 安装需要 HTTPS 安全上下文；接入域名证书后，将 Nginx 的 443 请求反向代理到同一个 Node 端口即可，无需增加手机客户端服务器。

## 3. 新服务器安装环境

以下命令适用于 Ubuntu 22.04：

```bash
sudo apt update
sudo apt install -y unzip curl nginx mysql-server

# 安装 Node.js 20 LTS（NodeSource）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

node --version
npm --version
nginx -v
mysql --version
```

安装完成后应看到与当前参考部署接近的 Node.js 20.x、npm 10.x 和 Nginx 1.18.x；这些版本是现有部署示例，不代表最新版推荐。

## 4. 部署目录和用户

```bash
sudo useradd --system --home /opt/hr-system --shell /usr/sbin/nologin hrsystem || true
sudo mkdir -p /opt/hr-system
sudo chown -R hrsystem:hrsystem /opt/hr-system
```

将源码包解压到 `/opt/hr-system`。确保目录中包含 `index.html`、`login.html`、`js/`、`css/` 和 `server/server.js`。

## 5. systemd 服务

创建 `/etc/systemd/system/hr-system.service`：

```ini
[Unit]
Description=HR Personnel Management System
After=network.target

[Service]
Type=simple
User=hrsystem
Group=hrsystem
WorkingDirectory=/opt/hr-system
ExecStart=/usr/bin/node /opt/hr-system/server/server.js
Restart=always
RestartSec=5
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable hr-system.service
sudo systemctl start hr-system.service
sudo systemctl status hr-system.service --no-pager
```

## 6. Nginx 反向代理

创建 `/etc/nginx/sites-available/hr-system`：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name YOUR_ECS_IP;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用配置：

```bash
sudo ln -sfn /etc/nginx/sites-available/hr-system /etc/nginx/sites-enabled/hr-system
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

## 7. 发布更新流程

2026-11-11 发行版可使用 [`deploy/aliyun-2026-11-11.sh`](../deploy/aliyun-2026-11-11.sh)。脚本固定部署已审核的 `39cbf2f` 提交，并核对源码包 SHA-256，只覆盖清单中的 36 个代码和说明文件。它适用于 `/opt/hr-system`、`hr-system.service`、`hrsystem` 用户，服务工作目录必须为 `/opt/hr-system`。启用 MySQL 时，应用必须连接 `127.0.0.1` 或 `localhost` 的 3306 端口，root 能通过本机 socket 备份同一实例；远程数据库、其他端口或不符合条件的环境会停止，不应跳过检查。实际 `HR_DATA_DIR` 若使用相对路径，会按服务进程的工作目录解析。发行文件及其父目录不得使用符号链接。

将脚本上传到服务器后以 root 执行：

```bash
bash /tmp/aliyun-2026-11-11.sh
```

服务器无法访问 GitHub 时，在可联网的开发机下载对应提交的源码归档，通过阿里云 Workbench 上传到服务器，再指定本地归档：

```bash
HR_RELEASE_ARCHIVE=/tmp/hr-source-39cbf2f.tar.gz bash /tmp/aliyun-2026-11-11.sh
```

先执行本次文件的语法检查和 43 项测试，再短暂停止应用，备份整套程序、实际数据目录、生产配置、systemd/Nginx 配置及 MySQL。备份保存在仅 root 可访问的 `/root/hr-system-backups/` 下，每次使用独立目录。部署保留 `server/config.json`、实际 `HR_DATA_DIR`、依赖和数据库，不上传开发机的真实数据。服务启动后核对受保护文件与数据库快照未变，检查失败自动恢复上版代码并启动服务。

脚本不更改 Nginx 配置。存在大附件时，应检查实际 `client_max_body_size` 能容纳后端最多 20MiB 的请求；上面的示例采用 25m。服务重启后需重新登录。

### 7.1 首次管理员初始化

新版账号文件位于实际数据目录中的 `auth-users.json`，独立于 MySQL。若服务器没有该文件，管理员须先初始化。可通过 SSH 本地转发打开服务器本机登录页，或上传 [`deploy/admin-setup.py`](../deploy/admin-setup.py)，在服务器终端运行：

```bash
python3 /tmp/admin-setup.py
```

由管理员本人输入至少 12 位密码并再次确认，终端不会回显输入；无法隐藏输入或没有可用的交互式终端时，脚本会停止。不要把密码写到命令参数、历史或聊天中。脚本使用服务器回环接口完成初始化，并验证管理员能读取现有人员资料，只输出数量。公网初始化被禁止。初始化完成后以 `admin` 登录，在权限管理中关联既有人员账号并分配楼长及负责楼栋。

## 8. 发布后验证

服务器内验证：

```bash
systemctl is-active hr-system.service
systemctl is-active mysql
curl -I http://127.0.0.1:8080/
curl -sS http://127.0.0.1:8080/api/auth/status
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/data/snapshot.json
ss -ltnp | grep -E ':80|:8080'
```

公网验证：

```bash
curl -I http://YOUR_ECS_IP/
curl -sS http://YOUR_ECS_IP/api/auth/status
curl -sS -o /dev/null -w '%{http_code}\n' http://YOUR_ECS_IP/api/data/snapshot.json
```

认证状态应为 200，匿名业务快照应为 401，`/server/config.json` 与 `/server/data/auth-users.json` 应为 404，旧微信、飞书登录接口应为 410。公网 `setupAllowed` 应为 false。

浏览器验证手机号注册与登录、个人资料、请假/加班和自己的小时数；楼长仅看到负责楼栋，管理员看到全部。发布后若页面仍旧，使用 Ctrl+F5 或检查 `index.html` 的脚本版本参数。不要在生产库创建验收用虚假人员账号。

MySQL 数据验证：

```bash
mysql --protocol=socket -uroot -e "SELECT table_name FROM information_schema.tables WHERE table_schema='hr_system';"
mysql --protocol=socket -uroot hr_system -NBe "SELECT COALESCE(JSON_LENGTH(payload,'$.employees'),0) FROM system_snapshots WHERE snapshot_key='default';"
```

## 9. 回滚

### 2026-11-12 组织配置修复

该次修复将人员下拉选项和楼栋负责人显示迁移到实际数据目录的 `organization-settings.json`。恢复必须从部署前的 `previous-code.tar.gz` 或 `application.tar.gz` 仅读取 `js/employees.js`，不得运行旧脚本、覆盖现有业务快照或恢复旧账号。

```bash
# 只核对数量；不输出原选项或负责人姓名，不创建配置
python3 deploy/recover-organization-settings.py --archive /root/BACKUP/previous-code.tar.gz --data-dir /opt/hr-system/server/data
```

确认来源后，在具有完整备份和回滚保护的修复流程中加 `--apply` 创建文件。已有配置会拒绝覆盖。root 执行时默认属主 `hrsystem`、权限 `600`。真实配置、账号和恢复数据不提交公开仓库。楼长显示与权限分配是两套独立数据，恢复显示不自动授予角色。

该修复使用新的提交与匹配的源码归档，不使用固定旧提交的 `aliyun-2026-11-11.sh`。发布后除原登录和权限边界外，验证公开组织选项不含楼长、登录配置按楼栋过滤、原业务数据与账号哈希不变。

### 常规回滚原则

自动回滚只恢复本次替换的前后端代码，保留已存在的数据、账号和配置。完整灾难恢复时，先暂停写入、另存当前状态，再由维护人员确认要恢复的整套程序、实际数据目录、账号文件及 MySQL 备份；不要直接用旧业务快照覆盖上线后的新资料。恢复后执行内外网健康检查和登录验证。
