# 06 运维与安全

## 1. 日常健康检查

```bash
sudo systemctl is-active hr-system.service
sudo systemctl is-active nginx.service
curl -fsS http://127.0.0.1:8080/ > /dev/null
curl -fsS http://127.0.0.1:8080/api/feishu/login-config
df -h
free -h
```

公网检查：

```bash
curl -I http://YOUR_ECS_IP/
```

## 2. 日志

systemd 日志：

```bash
sudo journalctl -u hr-system.service -n 100 --no-pager
sudo journalctl -u hr-system.service -f
sudo journalctl -u nginx.service -n 100 --no-pager
```

Nginx 默认日志：

```bash
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

不要把 `server/config.json`、请求体、用户快照或飞书 Token 写入日志。

## 3. 数据备份

至少备份以下内容：

```bash
sudo tar -czf /opt/hr-backup-$(date +%F).tar.gz \
  /opt/hr-system/server/data \
  /opt/hr-system/server/config.json
sudo mysqldump --single-transaction --routines --triggers hr_system \
  > /opt/hr-backup-$(date +%F)-mysql.sql
```

备份文件应复制到独立存储或阿里云 OSS，不能只留在同一块云盘。备份完成后检查压缩包可读，定期做一次恢复演练。

## 4. 数据恢复

1. 停止 `hr-system.service`。
2. 将 MySQL 备份导入 `hr_system`：`mysql hr_system < hr-backup-YYYY-MM-DD-mysql.sql`。
3. 如需灾备回退，再将 `server/data` 恢复到 `/opt/hr-system/server/data`，并关闭 MySQL 主存储配置。
4. 将 `config.json` 恢复到 `/opt/hr-system/server/config.json`，设置 `hrsystem:hrsystem` 所有者和 `600` 配置权限。
5. 启动服务并检查快照人数、页面和数据库连接日志。

不要在未备份的情况下使用 `/api/data/*.json` 的 DELETE 接口，也不要在系统管理中点击“重置数据”后再尝试恢复浏览器缓存。

## 5. 安全基线

- SSH 使用密钥登录，关闭密码登录；如果暂时使用密码，完成部署后立即更换临时密码。
- 安全组只开放 22、80；配置 HTTPS 后再开放 443，保持 8080 关闭公网访问。
- 将 SSH 22 来源限制为管理员固定公网 IP。
- `server/config.json` 权限保持 `600`，目录归属 `hrsystem:hrsystem`。
- App Secret 不写入 HTML、JS、README、截图和工单。
- 飞书应用使用最小权限和明确的可用范围，发布版本前核对机器人可见范围。
- 公开站点建议使用域名、HTTPS、有效证书和定期证书续期。
- MySQL 只监听 `127.0.0.1`，数据库密码保存在 `/etc/hr-system/mysql.env`，权限保持 `600`。
- 当前 API 尚未实现服务端登录鉴权；localStorage/sessionStorage 不能替代生产安全边界，公开部署前应补充服务端会话或 JWT 校验及写接口权限检查。

## 6. 常见故障排查

### 页面打不开

1. 检查阿里云安全组 TCP 80 是否放行。
2. 检查 `systemctl is-active hr-system.service`。
3. 检查 `ss -ltnp` 是否监听 80 和 8080。
4. 查看 Nginx 错误日志和 systemd 日志。

### 502 Bad Gateway

通常是 Node 服务停止或 8080 监听地址错误：

```bash
sudo systemctl restart hr-system.service
curl -I http://127.0.0.1:8080/
sudo nginx -t
```

### 微信登录失败

- 检查微信开放平台授权回调域名是否为当前公网域名，完整回调地址是否为 `http://YOUR_ECS_IP/api/wechat/callback`。
- 检查 AppID、AppSecret、服务端时间和 `api/wechat/login-config`。
- 未配置凭据或登录开关关闭时，登录页不会显示微信按钮；这是预期行为。

### 飞书消息发送失败

- 检查机器人能力是否开启。
- 检查 `im:message` 或后台对应的“获取与发送单聊、群组消息”权限。
- 群聊接收对象必须是 `chat_id`，且机器人已加入群聊。
- 用户接收对象必须使用正确的 `open_id`、`user_id` 或 `union_id` 类型。

### 更新后仍显示旧页面

- 检查 `index.html`、`login.html` 的资源版本参数。
- 执行 `systemctl reload nginx`。
- 使用 Ctrl+F5，检查浏览器 Network 是否命中最新 JS/CSS。
- 确认服务端没有残留旧工作目录或旧 systemd `ExecStart`。

## 7. 变更记录建议

每次上线记录日期、版本标识、修改文件、数据备份位置、执行人、验证结果和回滚包位置。飞书 App ID 可以记录，App Secret 和 Token 不记录。
