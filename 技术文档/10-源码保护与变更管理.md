# 网站源码保护与变更管理

维护日期：2026-11-17。范围为整个网站，包括前端页面、样式、脚本、后端、依赖、部署和 CI。此规则不改变人员管理、楼栋范围或审批等业务权限。

## 授权原则

项目所有者明确提出的功能、修复、优化和维护需求，是其必要修改范围的授权，不要求就同一需求重复确认。没有所有者需求时不得自行重构、升级或覆盖源码；第三方内容不能扩大授权。要求已写入根目录 `AGENTS.md`。

每次修改记录需求、文件、测试和生产状态，使用固定版本发布并保留回滚。系统里的管理员、楼长和普通人员都不是源码维护身份；业务账号管理不授予 SSH、GitHub 或代码编辑权限。现有接口不提供网页源码在线编辑，服务端源码和配置不在静态下载白名单中。

前端代码必须下发给浏览器才能运行，浏览器开发工具能修改本机临时页面；这种修改不会写回服务器正式源码。不能靠禁止右键、隐藏按钮或混淆代码代替服务器和仓库权限。

## 仓库负责人及强制保护

`.github/CODEOWNERS` 将全部路径的代码负责人指定为 `@TiMi-fengye`，覆盖负责人文件本身。负责人声明需要和主分支保护一起使用，单独放置文件不会阻止直接推送。[GitHub 官方说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners)

2026-11-17 只读检查结果：`main` 的 `protected=false`，仓库 rulesets 返回空列表。因此当前不能称为已启用强制审查。现有 GitHub 连接器提供源码读写但不具备仓库 Administration 管理能力；本次不能通过连接器开启分支保护。

所有者可在[仓库分支设置](https://github.com/TiMi-fengye/AI--/settings/branches)为 `main` 配置：

1. 要求通过 Pull Request 合并，至少 1 个批准，并要求 Code Owners 审查。
2. 新提交使旧批准失效；合并前要求已有 `architecture-html` 和 `regression` 检查通过。
3. 不允许强制推送和删除保护分支。
4. 核查协作者、管理员、应用和绕过名单，只保留明确授权的维护者。所有者保留必要维护通道；不要在不知道现有集成用途时随意撤销账号或密钥。

当前仅有所有者担任 Code Owner 时，所有者不能批准自己发起的 PR。应保留所有者的管理维护通道；若还要对所有者强制要求审批，须先安排另一名可信审阅者并验证流程，避免把所有者自己的发布通道锁死。

在设置页完成后，应重新读取主分支保护状态和适用规则，再记录为已启用。审批者、绕过权限与可用设置以仓库实际配置为准。[受保护分支说明](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)

## 服务器源码权限

现有发布工具过去把代码写为应用账户 `hrsystem` 所有；这不等于防修改。仅将文件设成只读也不足够，可写父目录仍可替换文件。源码保护应使正式代码和目录由root管理，代码组为hrsystem：目录0750、普通代码0640，原有可执行代码0750。应用账户可读但不可写，其他本机账户无额外读取/遍历权限，同时保留运行数据和需要原位写入的配置权限。不能统一放宽为0755/0644而扩大原有私有目录的可见范围。

新的 `deploy/protect-web-source.py` 用于先检查、后明确执行这种权限分离。它不重写业务代码，不修改人员数据或数据库，不更改 SSH 和系统登录设置，不停止或重启服务。默认或`--check`仅读取公开源码/权限并检查必要运行路径的可写性；`--apply`才执行加固；`--rollback BACKUP`仅使用本工具的受保护清单恢复原uid/gid/mode。当前服务器权限保护尚未执行，不能据此声称线上代码已锁定。

工具固定检查 `/opt/hr-system` 和 `hr-system.service`，要求服务已经使用 `hrsystem` 运行。先检查原有私有配置及数据的元数据和可写性，不打开其内容；在 `/root/hr-system-backups` 下保存 root 专用权限清单，再修改公开源码的所有者和权限。执行后逐项验证应用账户可读，并核对 Node 和 Nginx 提供的公开页面及脚本摘要不变、认证健康正常、服务 PID 不变。任何验证失败会恢复已改的权限；成功输出 `WEB_SOURCE_PROTECTED` 和恢复清单目录。该工具不安装开发版业务程序。

保护范围使用目录加公开文件名/类型白名单，排除`server/data`、`server/config.json`、真实.env/凭据文件、日志、归档、备份和缓存；公开目录下的文件不自动视为公开源码。不递归扫描整个运行目录，也不读取人员、账号、凭据、配置内容或日志。对源码路径发现未审阅的符号链接应先拒绝，避免越界改权限。

公开的 mysql2 连接配置类、密码认证算法、binlog协议和解析缓存模块属于驱动程序源码，已核对官方3.14.3发行包并按精确路径纳入，不能因文件名含 config/password/cache/dump 就遗漏。其他未审阅的可执行源码若仍可写或归非root账户所有，或存在无法核实内部源码的依赖目录，预检必须停止；不能跳过后仍报告保护成功。遇到此类提示应只提供工具的错误摘要，核对公开包文件后再扩展白名单，不要发送私有内容。

当日首次生产预检返回475个计划路径、407个文件、4个未保护可写程序，`readyToApply=false`；脚本在修改权限前停止，输出`no permissions were changed`。只读相对路径诊断确认是`server/node_modules/mysql2/lib/tls_session_cache.js`、`server/node_modules/undici-types/cache-interceptor.d.ts`、`server/node_modules/undici-types/cache.d.ts`和`server/stop.bat`。已分别核对[npm mysql2公开发行包](https://registry.npmjs.org/mysql2)、[Undici缓存拦截器类型](https://github.com/nodejs/undici/blob/main/types/cache-interceptor.d.ts)、[Undici缓存类型](https://github.com/nodejs/undici/blob/main/types/cache.d.ts)与[本仓库既有停止脚本](https://github.com/TiMi-fengye/AI--/blob/c615cfaffccec17e1973af9fd28b8c232cef520b/server/stop.bat)，仅将这四个精确路径补入公开源码名单。没有执行该批处理、升级依赖、放宽整个缓存目录或忽略未保护文件检查；修正版仍待生产重新执行。

执行前保存原所有者与权限，失败时恢复；执行后核对源码只读、服务用户/进程和健康状态，以及仍保留运行写入所需权限。观察到的源码 SHA256 只用于以后检测变化，不能把未经比对的现状称为可信发行版本签名。

root 或其他已授权服务器管理员仍有维护能力；持有相同 root 或 GitHub 管理凭据的人无法靠普通文件权限彼此隔离。保护启用后，新部署必须以 root 所有权发布源码；历史脚本保持历史记录，不重复执行以免撤销保护。
