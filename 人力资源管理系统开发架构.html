认证与授权约束
  • 密码采用随机盐与 scrypt 哈希，账号不依赖浏览器本地存储。
  • Cookie 使用 HttpOnly、SameSite=Lax，有效期 12 小时；HTTPS 时附加 Secure。
  • 匿名业务快照返回 401；账号、配置和运行数据路径不对外提供。
  • 楼长和普通人员的读取与写入范围均在服务端校验。
  • 短信验证已开发、默认关闭；统一身份平台和多实例共享会话需另行扩展。
  • 验证码仅以 HMAC 摘要保存在内存，API 和磁盘不返回明文；未配置短信时不能伪装发送成功。
  • 楼长名单表示管理员任命，不是在线状态。退出登录或人员档案标为离职不会自动撤权；管理员须调整账号角色或负责楼栋。空姓名不回退登录账号或手机号。

CHAPTER 06

数据存储与请求流

业务快照、账号和会话分别保存；写入先验证范围与版本，再合并并持久化。

业务主快照

MySQL · hr_system.system_snapshots

启用 MySQL 后使用 default 快照行持久化人员、考勤、申请等业务。人员工号为独立文本字段 employeeNo，入职日期沿用 joinDate；内部 id 及 employeeId 关联不变。采用共享 JSON 快照模型，并非按每种实体拆分关系表。

备份要点：停写窗口内备份 MySQL；校验快照哈希与记录数量。

JSON 数据

实际 HR_DATA_DIR / snapshot.json

关闭 MySQL 时作为业务存储；启用 MySQL 时用于初始化与灾备。不能假定该文件始终与数据库实时一致。

备份要点：随实际数据目录备份；还原前核对数据来源与时间。

组织与表单配置

实际 HR_DATA_DIR / organization-settings.json

独立保存真实下拉选项及暂无人员的楼栋；发布和业务快照导入导出不覆盖配置。旧手填楼长条目保留供备份核对，不再作为看板显示或权限来源。

备份要点：随实际数据目录备份，权限600、属主为应用用户；可由部署前代码备份安全提取。

账号与恢复资料

实际 HR_DATA_DIR / auth-users.json

账号、角色、负责楼栋和密码哈希独立于业务快照；楼长名单按当前授权账号生成，优先使用有效绑定人员姓名，否则使用账号姓名。旧浏览器恢复副本也位于受保护的数据目录。

备份要点：备份实际数据目录，限制文件权限，禁止提交公共仓库。

会话与页面状态

服务端内存 / 浏览器内存

会话通过 HttpOnly Cookie 关联；当前业务范围在浏览器内存保存，每次登录重新获取。服务器重启后重新登录。

备份要点：不将会话当作持久资料；业务以服务端确认的保存结果为准。

短信发送配额

实际 HR_DATA_DIR / sms-rate-limits.json

持久化同手机号冷却、手机号/IP/系统发送限额，键为哈希。验证码及挑战仅在内存，重启失效，配额不随重启清空。

备份要点：受保护文件权限600，随实际数据目录备份；不包含明文验证码、手机号或IP。

一次保存如何完成

  1. 浏览器通过同源请求携带 hr_session Cookie。
  2. Node 验证会话与角色，根据 employeeId 或 buildings 计算可见人员。
  3. 读取接口只返回可见范围，避免先传全量再由菜单隐藏。
  4. 保存请求校验来源、字段、业务权限与 revision，旧快照返回 409。
  5. 服务端合并范围内变更并持久化；浏览器等待确认后提示成功。
