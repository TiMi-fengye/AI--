# 03 后端技术说明

> 历史说明：本文保留旧版接口记录。当前后端请以 [架构 HTML](../人力资源管理系统开发架构.html)、[07-手机号账号与数据权限](./07-手机号账号与数据权限.md) 和实际代码为准。服务端已实现账号、会话、角色范围及 revision 冲突检查；微信/飞书登录接口已停用。下文“无服务端鉴权”、匿名快照及最后写入覆盖描述不再适用，请勿据此操作生产。

## 1. 服务端定位

`server/server.js` 是一个基于 Node.js 内置模块的 HTTP 服务，同时承担四项职责：

1. 托管项目根目录下的 HTML、CSS、JS、图片和表格。
2. 提供服务器快照读写接口。
3. 代理微信 OAuth、飞书 Token 和消息请求，避免 AppSecret/App Secret 出现在浏览器。
4. 输出状态码、JSON 错误和静态资源不缓存响应头。

服务启动后监听 `0.0.0.0:8080`。生产环境不直接让互联网访问 8080，而是由 Nginx 在 80 端口接收请求。

> 认证边界：当前 API 尚未实现服务端会话或 JWT 鉴权，前端 localStorage/sessionStorage 不能作为生产安全边界。公开部署前需要补充服务端登录校验，并为写接口增加权限检查。

## 2. 服务端文件

| 文件 | 作用 |
|---|---|
| `server/server.js` | HTTP 服务和所有服务端路由 |
| `server/config.json` | 端口、微信登录凭据、飞书应用配置和接收对象 |
| `server/data/snapshot.json` | MySQL 初始化来源和灾备快照 |
| `server/package.json` | `mysql2` 数据库驱动依赖 |
| `server/launch.vbs` | Windows 环境后台启动辅助文件 |
| `server/stop.bat` | Windows 停止服务脚本 |

## 3. 静态资源处理

服务端将 URL 映射到项目根目录，并限制路径必须位于项目根目录内。主要 MIME 类型包括：

- `.html`：`text/html; charset=utf-8`
- `.css`：`text/css; charset=utf-8`
- `.js`：`application/javascript; charset=utf-8`
- `.json`：`application/json; charset=utf-8`
- `.png`、`.jpg`、`.ico`
- `.xlsx`：Office Open XML 表格类型

HTML、CSS、JS 和 JSON 响应使用 `no-store/no-cache`，用于降低更新后仍加载旧资源的概率。

## 4. API 清单

### 4.1 数据快照

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/data/snapshot.json` | 读取服务器快照 |
| POST | `/api/data/snapshot.json` | 保存前端上传的快照 |
| DELETE | `/api/data/<key>.json` | 删除指定数据文件，运维操作慎用 |

参考部署启用 MySQL 后，快照接口以 `hr_system.system_snapshots` 表为主存储，JSON 文件仅用于初始化和灾备。前端仍以完整快照提交，多管理员同时修改同一数据时，以最后一次完整快照为准。

### 4.2 飞书接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/feishu/config` | 获取或保存 App ID、接收对象和消息配置；App Secret 不返回前端 |
| GET/POST | `/api/feishu/login-config` | 获取或保存登录启用、自动建号和 OAuth 回调地址 |
| GET | `/api/feishu/auth-url` | 创建浏览器 OAuth 授权地址和一次性 state |
| POST | `/api/feishu/auth-code` | 接收工作台 `requestAccess/requestAuthCode` 的 code 并换取用户身份 |
| GET | `/api/feishu/callback` | 浏览器 OAuth 回调 |
| POST | `/api/feishu/test` | 发送飞书测试消息 |
| POST | `/api/feishu/send` | 发送文本消息 |

### 4.3 MySQL 快照存储

服务启动时使用 `mysql2/promise` 连接 MySQL，自动创建 `system_snapshots` 表；如果表中没有 `default` 行，会从 `server/data/snapshot.json` 导入。MySQL 连接信息通过 systemd 的 `/etc/hr-system/mysql.env` 注入，数据库账号只授予 `hr_system` 库权限。

### 4.4 通用处理

所有 JSON 请求通过 `readRequestBody()` 读取，单次请求体上限为 1 MB。JSON 解析失败会返回 400；微信或飞书远程调用失败会返回 502，并将第三方错误信息转换为用户可读提示。

## 5. Token 处理

- `feishuToken()` 获取并缓存 `tenant_access_token`，用于应用身份发送消息。
- `feishuAppAccessToken()` 获取并缓存 `app_access_token`，用于 OAuth 授权码换取用户 Token。

### 4.5 微信登录接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/wechat/login-config` | 获取或保存微信 AppID、启用状态、自动建号和 OAuth 回调地址；AppSecret 不返回前端 |
| GET | `/api/wechat/auth-url` | 创建微信扫码授权地址和一次性 state |
| GET | `/api/wechat/callback` | 接收微信授权码，换取 OpenID/UnionID 后通过 `postMessage` 返回登录页 |

微信登录使用微信开放平台网站应用的 `snsapi_login` 扫码流程。系统只保存已校验的身份标识，不保存微信密码或访问令牌。
- Token 过期时间会提前约 60 秒失效，下一次调用重新获取。
- App Secret 只从服务端 `config.json` 读取，不能写入前端 JS、HTML 或日志。

## 6. 服务进程

生产服务由 systemd 管理，服务名为 `hr-system.service`，应用用户为 `hrsystem`。常用命令：

```bash
sudo systemctl status hr-system.service
sudo systemctl restart hr-system.service
sudo systemctl is-active hr-system.service
sudo journalctl -u hr-system.service -n 100 --no-pager
```

服务进程不需要 root 权限；只有安装软件、修改 Nginx、修改 systemd 和读取受保护配置时使用 sudo。

## 7. 后端开发规范

1. 新接口先定义 HTTP 方法、请求体、成功响应和错误响应。
2. 不在响应、异常堆栈或日志中打印 App Secret、Token 和完整人员快照。
3. 文件路径必须经过根目录边界校验。
4. 所有异步 `fetch` 都要检查 HTTP 状态以及微信 `errcode` 或飞书 `code`。
5. 改动 `config.json` 前要备份；改动数据结构时提供兼容迁移。
6. 当前部署参考使用 Node.js 20；其他版本需自行验证兼容性，本文不构成最新版推荐。
