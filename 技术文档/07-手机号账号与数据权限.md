# 手机号账号与数据权限

适用版本：2026-11-11 起。本文替代旧文档中有关浏览器本地账号、微信或飞书登录、匿名快照访问的说明。

## 注册与个人资料

登录页提供手机号注册、手机号加密码登录，并兼容管理员维护的管理账号。注册需填写人员信息表单中的姓名和手机号，设置至少 8 位密码并确认；手机号为 11 位中国大陆手机号。短信验证码功能已开发，默认关闭，开通服务后启用；启用时注册和手机号登录均需验证码，登录仍需密码。短信验证号码当次可收件，不等同于人员实名审核。详见 [09-短信验证码接入](./09-短信验证码接入.md)。

人员性质（`company`）、人员属性、工作属性、部门、状态、楼栋都是选填项，默认保持空值，不自动分配组织。其余字段沿用原人员表单，资料及附件可在注册时提交，也可随后通过“我的资料”补充。普通人员登录后首先看到个人档案，人员关联使用唯一 `employeeId`，不按姓名识别。

2026-11-13 起，人员添加、编辑及注册表单增加选填工号，使用文本字段 `employeeNo` 保存，保留前导零。“我的资料”可核对和维护自己的工号。人员列表的“编号”列改为实际工号，并补充部门、楼栋、邮箱和入职日期（`joinDate`）；个人资料和人员详情同步展示。旧档案未填工号时列表显示“未填写”，不自动用内部编号代替。工号属于档案资料，内部人员 `id` 及账号、申请、考勤关联的 `employeeId` 保持不变，修改工号不会改变身份关联或授予管理权限。

已有人员档案使用相同手机号时，注册不会自动接管该档案。管理员在“系统设置 → 权限管理”中创建或关联账号。已绑定的登录手机号不能从人员表单中改动；本版本暂不支持已有手机号账号换号。

## 角色与数据范围

| 角色 | 数据范围 | 功能 |
| --- | --- | --- |
| 管理员 `admin` | 全部 | 人员、考勤、申请审批、小时数、费用、绩效、组织、账号及设置 |
| 楼长 `leader` | 管理员明确分配的 `buildings` | 本楼栋人员维护、考勤、申请及审批、小时汇总、费用和绩效 |
| 普通人员 `user` | 绑定的个人 `employeeId` | 查看维护自己的资料、提交自己的加班和请假申请、查看自己的小时数 |

普通人员不显示全员看板、人员列表、签到和月报、费用、绩效、组织或系统设置，也不能审批、编辑或删除已提交申请。小时数按已批准记录计算，区分费用加班、调休加班、已使用调休和剩余调休。岗位名称或自己填写的楼栋不会授予楼长身份；楼长角色及其楼栋范围只能由管理员分配。

权限在服务端强制执行。匿名请求不能获取业务快照；普通账号收不到其他人员记录；楼长收不到其他楼栋记录。范围内保存以合并方式处理，保留其他人员、楼栋的数据。快照携带 `revision`，旧版本写入返回 409，客户端撤回未获确认的修改并重新读取当前范围。

## 考勤管理记录删除（2026-11-18）

本功能于2026-11-18开发、2026-11-19定向发布并收到`ATTENDANCE_DELETE_OK`成功回执。在“考勤管理”的考勤、加班申请、请假申请三个列表中，删除按钮统一仅管理员可见；管理员确认后提交，等待服务器保存成功才提示完成。请假列表为待审批、已批准、已拒绝的记录均提供管理员删除入口。楼长和普通人员无删除按钮，直接调用页面方法或发送快照也不能删除。

后端在快照范围合并时保留已有记录，阻止非管理员通过清空有效范围内的记录、遗漏行或变更编号删除。普通人员快照中不提供考勤记录的空列表仍按原规则处理，不会清除服务端考勤。如果楼长删除人员会连带移除考勤、加班或请假记录，该操作也被拒绝，须联系管理员处理；没有这三类关联记录的人员仍按原权限维护或删除。历史上已无人员关联的孤儿记录保持原样，不在楼长正常保存时顺便清理；绩效等无关模块沿用原规则。

楼长在授权楼栋内原有的申请审批、加班编辑、签到/签退及资料维护保持；普通人员仍只提交自己的申请、查看自己的资料和小时数。管理员删除同样保留调休余额约束：若删除已批准的调休加班会导致已有调休透支，服务器拒绝保存并提示，不能以删除操作绕过。

上次已上线的三种新请假类型、外包年假/病假名称和分钟时间保持。本次已精确修补生产认证模块并发布三份前端脚本，后端已重启，原内存会话失效，需重新登录并刷新；发布前已生成并校验完整私有备份，`sourceProtected=true`、`dailyBackupTimerPreserved=true`、`businessDataWritten=false`。固定发布版本为`b85a98ec25cf1f3f0564b3bc7006f27096954d9b`，Linux CI全部271项通过，回滚及备份地址见[部署手册](05-阿里云部署手册.md)。

独立公开复核确认三份脚本与发布候选逐字节一致，ETag返回304且gzip解压一致；认证状态正常，匿名业务接口401，私有配置和账号文件404。未读取真实人员资料、未进行生产记录删除或实号浏览器验收。验收后文档及固定架构HTML只同步本地和GitHub，不为补记文档再次部署程序或重启服务。

## 首次管理员设置

在运行 Node.js 服务的本机访问 `http://localhost:8080/login.html`，点击初始化管理员入口并设置至少 12 位密码。该初始化接口仅限本机回环连接，不允许公网请求初始化。远程服务器可通过 SSH 本地端口转发访问服务器的 localhost 完成此步骤。初始化完成后，使用账号 `admin` 登录，再分配楼长角色及负责楼栋。

普通手机号注册不依赖管理员初始化，但注册不能授予管理权限。服务端账号文件为 `server/data/auth-users.json`，密码使用随机盐与 scrypt 哈希；业务快照继续保存到原 JSON/MySQL 数据源。会话 Cookie 为 HttpOnly、SameSite=Lax，有效期 12 小时，HTTPS 时使用 Secure；服务重启后须重新登录。

## 旧浏览器资料迁移与恢复

首次登录时，若检测到旧版浏览器人员资料或账号，先向服务器保存独立恢复备份，再清除旧共享缓存。备份目录为 `server/data/legacy-browser-backup-<账号哈希>/snapshot-0.json` 至 `snapshot-4.json`，每个账号保留最近五份。旧账号仅保存白名单元信息和密码哈希，不保存明文密码，不会通过备份自动启用账号。

管理员首次登录且服务器人员列表为空时，会把旧浏览器人员快照迁移为服务端数据；服务器已有人员时不会用旧缓存覆盖。可迁移的旧普通密码账号也会由管理员身份逐个导入；无法自动迁移的账号应在权限管理中重新开通。原第三方登录身份不会恢复。

若网络或旧数据校验导致迁移失败，原始恢复副本仍在上述受保护目录。管理员可在服务器上选择正确备份，将人员快照通过系统数据导入恢复；账号哈希恢复应由有服务器权限的维护人员检查后进行，不能将备份中的角色直接当作已授权身份。发布时务必同时备份 `server/data`、MySQL 和服务端配置，不要上传实际账号、人员信息或恢复副本到公开仓库。

客户端当前业务数据以内存为准，每次登录重新获取当前账号的服务端范围，避免共享浏览器遗留其他账号数据及大附件导致 localStorage 配额错误。保存成功提示须等待服务器确认。

## 人员表单与组织配置

真实下拉选项独立保存在实际 `HR_DATA_DIR/organization-settings.json`，不写入公开 JavaScript，也不随业务快照导入导出覆盖。配置包含人员性质、人员属性、工作属性、岗位、部门、状态、楼栋、区域和机房，也保留暂无人员的楼栋。缺少某组配置时可由已存人员字段推导；明确配置的空列表会保留。编辑时保留人员已有值，避免被下拉首项替换。2026-11-12 恢复的手填楼长名单可继续留在受保护的旧配置和备份中，本次自动名单功能不再将它作为展示来源。

`GET /api/organization/options` 仅返回注册所需下拉，不包含楼长姓名、电话或人员资料。登录后 `GET /api/organization/settings` 每次按当前授权账号生成楼长名单：管理员获取全部范围，楼长仅获取负责楼栋的名单，普通人员不获取楼长名单。`POST /api/organization/settings` 仅管理员可维护组织选项，并验证独立配置的 revision；显式提交手填 `buildingLeaders` 会返回 400，提示到“账号与人员权限”维护。更新组织选项不会授予账号楼长角色。

从旧备份恢复时可使用 `deploy/recover-organization-settings.py`，默认只检查数量；加 `--apply` 原子创建且拒绝覆盖。恢复工具不执行旧 JS，不恢复旧快照或账号。文件须属应用用户 `hrsystem`、权限 `600`，与业务数据目录一并备份。

## 楼长自动名单与人员更换（2026-11-13 开发更新）

本次开发将看板的楼长姓名改为从服务端当前账号权限自动生成，生产生效以本次部署验收为准。操作流程如下：

1. 新楼长通过手机号注册并填写个人档案。新注册账号仍为普通人员，自填岗位或楼栋不能获得楼长权限。
2. 管理员进入“系统设置 → 权限管理”，关联人员档案，将账号角色设为“楼长”，明确分配负责楼栋。
3. 该账号登录后按楼长范围使用系统。看板读取组织接口时会显示该楼栋的当前授权楼长，无需再维护一份姓名表。
4. 楼长更换时，管理员调整旧账号角色或负责楼栋，或删除旧账号，再为新账号分配权限。删除账号会保留人员档案。

名单只取 `role=leader` 账号及其明确分配的 `buildings`。姓名优先取有效 `employeeId` 绑定的人员姓名，否则使用账号姓名；没有可用姓名时跳过，不以登录账号或手机号代替姓名。同一楼栋可以显示多名已授权楼长，显示文本去重不改变账号或人员身份关联。

每次进入或重绘看板时重新读取名单；停留看板时，窗口重新聚焦或页面重新可见会触发只读刷新。管理员保存权限或删除账号后也会重读。同步期间显示正在同步，读取失败显示同步失败，不回退旧手填姓名；组织下拉选项继续保留。此功能没有轮询或实时推送。

名单表示管理任命，不表示当前在线人员。退出登录、关闭浏览器或把人员档案状态改为“离职”不会自动撤销楼长权限；调离时须由管理员调整账号角色或楼栋范围。旧手填配置、恢复副本及备份均不会反向授予楼长权限。

## 人员信息导出（2026-11-16 开发更新）

2026-11-16 已定向发布并完成公开文件及接口边界验收，“人力资源”页面增加“导出人员”。管理员导出全部人员；楼长只导出管理员明确分配的楼栋人员，包含负责多个楼栋的情况。普通人员及匿名请求不允许批量导出；个人岗位、自己填写的楼栋、页面搜索条件和请求参数都不能扩大范围。

进入“人力资源 → 导出人员”，确认范围并选择格式。默认导出当前账号的完整授权范围，页面上的搜索和筛选不缩小导出；如需挑选记录，可在导出的表格中进一步处理。当前支持 12 种常用格式，而不是任意文件格式：

| 格式 | 用途与内容 |
| --- | --- |
| Excel `.xlsx`、旧版 Excel `.xls`、OpenDocument `.ods` | 人员表格；工号、手机号按文本保存，保留前导零 |
| `.csv`、`.tsv` | UTF-8 文本表格，正确处理分隔符、引号和换行；危险公式前缀加单引号按文本输出。Excel 自动识别类型可能去掉前导零，需要完整文本类型时优先 XLSX 或 JSON |
| `.json` | 完整人员档案结构，包含已保存的附件数据，适用于后续处理 |
| `.xml`、`.txt`、`.html` | 结构化、文本或可直接阅读的人员资料，表格格式展示附件文件名 |
| Word `.docx` | 真实 Open XML 文档；按人员分章，用字段和值两列展示资料 |
| `.zip` | 完整档案包，包含人员 JSON、CSV、附件清单及简历、证件原文件；附件保留原有文件字节与类型 |
| PDF | 打开可见打印预览并调用打印，通过浏览器“打印 → 另存为 PDF”保存；预览保留手动打印按钮 |

导出包含 20 个文字字段：工号、姓名、性别、岗位、人员性质、人员属性、工作属性、部门、状态、区域、机房、楼栋、手机号、邮箱、入职日期、离职日期、人员简介、简历文件名、证件文件名和简历提取文本。表格与阅读格式不展开附件的原始数据；需要完整附件时使用 JSON 或 ZIP。ZIP 按“附件 / 人员内部 ID / 简历或证件 / 安全文件名”组织路径，避免相同姓名、重复工号或附件同名覆盖。

容量与完整性限制：ZIP 未压缩内容合计最多 128 MiB、最多 65,535 个文件；附件损坏、只有文件名而没有内容或包超限时整体提示失败，不静默漏文件。电子表格单元格最多 32,767 个字符，超出时提示改用 JSON 或 ZIP。XLS 最多 65,536 行，XLSX / ODS 最多 1,048,576 行，均包含表头。CSV / TSV 是文本交换格式，不提供电子表格单元格类型；需保留前导零时选择 XLSX / JSON，或在外部表格软件导入时明确将对应列设为文本。

数据由 `GET /api/employees/export` 从服务端当前快照生成，不从浏览器表格、过期缓存或页面隐藏行拼出。接口等待在先的数据写入与快照读取完成后重新检查会话和角色，依据最新负责楼栋筛选；只返回 20 个文字字段及 `id`、`resumeData`、`credentialData`，不携带账号密码、哈希、令牌或其他业务集合。档案原有字符串保留空值和前导零，有限数字、布尔值转成文字，异常嵌套对象不展开；附件数据只接受字符串。匿名请求返回 401，普通人员返回 403，非 GET 方法返回 405。导出响应禁止缓存。客户端先等待待保存数据确认；请求失败、权限变化、账号切换或离开导出页面后不交付迟到的下载结果。

本功能不更改人员档案或账号权限。制作于当日较早时间的使用介绍视频尚未包含本次新导出入口；当前操作以本说明和固定架构 HTML 为准。部署文件、生产与开发版本边界见[部署手册 §7.4](05-阿里云部署手册.md#74-人员信息导出定向发布2026-11-16待生产验收)。

## 启动读取与缓存（2026-11-16 性能更新）

本次性能优化为开发更新，生产状态以新版本发布验收为准。每次登录仍须校验服务端会话，读取当前账号范围的业务快照和组织配置。启动时并发读取两组资料，初次看板复用本次启动已经取得的组织结果；以后进入、聚焦或恢复可见时，仍按既有机制刷新楼长任命。首次授权人员及其附件仍要加载，不用持久化旧人员缓存绕过读取。

内存 Store 读取和写入改为分离复制数组、对象等容器，避免重复把大附件字符串转换成 JSON 再解析。字符串不可变，保存后返回的数组和对象仍与内部数据隔离；修改读取副本不直接改动 Store。楼栋权限查询只读取目标人员的楼栋字段，不为每位人员复制整份人员及附件列表。数据仍仅存当前会话内存，不新增人员 `localStorage` 缓存，不改变工号、内部关联 ID、附件格式、保存版本或后端授权规则。

静态页面和脚本使用内容 ETag，浏览器每次重验证，相同内容可返回 304；客户端接受时，较大的文本资源使用 gzip。静态响应采用 `public, max-age=0, must-revalidate`，不能长期使用旧代码。业务 JSON 即使启用 gzip，仍保持 `Cache-Control: no-store`，不返回 ETag 或 Last-Modified，也不在服务端共享缓存账号、人员快照或附件。只有公开静态白名单文件进入有上限的内存资源缓存，修改文件后会重新检查并更新内容。

本次不改变权限或附件协议，减少的是重复处理、重复请求和传输字节，不能承诺真实网络与大文件场景固定加速倍数。基准若使用合成数据，应与实际设备、网络和附件内容的端到端耗时分开理解。原有介绍视频保持此前制作基线，没有新增本次性能内容。发布边界见[部署手册 §7.5](05-阿里云部署手册.md#75-启动与传输性能定向更新2026-11-16待生产验收)。
